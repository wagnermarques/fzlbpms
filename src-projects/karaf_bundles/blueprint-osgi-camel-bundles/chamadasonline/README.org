#+TITLE: chamadasonline

* Overview

The =chamadasonline= bundle is a native Karaf/Camel port of
https://github.com/wagnermarques/fzl-chamadasonline's backend (originally a
Fastify + Prisma app deployed on Render, with Supabase Postgres) — a school
attendance PWA with geofencing, rotating check-in codes, and
device-fingerprint fraud detection for ~2000 students.

It follows the same pattern as the =contatemeantes= bundle in this
directory: plain JDBC (no ORM), a dedicated Postgres role/database isolated
from =fzldb=/=moodle=/=contatemeantes=, deployed via Karaf's hot-deploy
folder. Unlike =contatemeantes=, this bundle enforces real authentication
(HMAC-signed Bearer tokens + Keycloak SSO) and per-route rate limiting,
since it carries PII and the whole point of the app is fraud resistance.

One deliberate improvement over the Node source: =KeycloakTokenVerifier=
actually verifies the RS256 signature of a Keycloak access token against the
realm's JWKS. The original =routes/auth.ts= only base64-decoded the token
payload and never checked the signature — anyone could forge a token client-
side. See =KeycloakTokenVerifier.java=.

* Endpoints

All under =/chamadasonline=, port =9094=. Ported 1:1 from
=apps/api/src/routes/{auth,events,checkins,devices}.ts= in the Node source —
see that repo for full request/response shapes; the field names are
unchanged (camelCase JSON in/out, snake_case columns in Postgres).

| Method | Path                                              | Auth        |
|--------+---------------------------------------------------+-------------|
| GET    | /health                                            | none        |
| POST   | /auth/login                                        | none        |
| POST   | /auth/keycloak                                     | none        |
| GET    | /auth/me                                           | any         |
| GET    | /events/active                                     | any         |
| POST   | /checkins                                          | STUDENT     |
| POST   | /events                                            | STAFF       |
| POST   | /events/{id}/periods                               | STAFF       |
| GET    | /events/{eventId}/periods/{periodId}/code          | STAFF       |
| GET    | /events/{eventId}/periods/{periodId}/checkins      | STAFF       |
| GET    | /events/{eventId}/flagged                          | STAFF       |
| PATCH  | /checkins/{id}/review                              | STAFF       |
| GET    | /students/lookup?registrationNumber=...            | STAFF       |
| POST   | /students/{id}/enrollment-code                     | STAFF       |
| POST   | /devices/enroll                                    | STUDENT     |

Rate limits mirror the Node source's fastify-rate-limit config, keyed per
client IP via the =X-Real-IP= header nginx sets: =/auth/login= and
=/auth/keycloak= 10/min, =/checkins= 5/min, =/students/{id}/enrollment-code=
30/min, =/devices/enroll= 10/min.

* Database

Dedicated database + role, created once directly in =fzl-postgresql=:

#+begin_src text
CREATE ROLE chamadasonline WITH LOGIN PASSWORD '...';
CREATE DATABASE chamadasonline OWNER chamadasonline ENCODING 'UTF8';
#+end_src

=OWNER= at creation matters on PostgreSQL 15+ — see =contatemeantes/README.org=
for why.

Schema: =src/main/resources/sql/schema.sql= — the 7 tables from
=apps/api/prisma/schema.prisma= (User/Event/EventPeriod/CheckinCode/Device/
DeviceEnrollmentCode/Checkin), ported 1:1 with the same unique constraints
and indexes. Requires the =pgcrypto= extension (for =gen_random_uuid()=),
created by the schema script itself. Applied manually for now, no migration
tool — same as =contatemeantes=.

Seed a staff account (schema.sql has the INSERT commented out at the
bottom — uncomment and fill in a real bcrypt hash, generated via
=PasswordUtil.hash(...)= or any jBCrypt-compatible tool) before testing
=POST /auth/login=.

Connection settings: =CHAMADASONLINE_DB_HOST/PORT/NAME/USER/PASS= env vars
(docker-compose.yml, service =fzl-karaf-camel-integration=), read via plain
=System.getenv= by =ChamadasOnlineDataSourceFactory= — same reasoning as
=ContatemeantesDataSourceFactory=.

* Keycloak

=keycloak-admin-camel-context.xml= registers a public =fzl-chamadasonline=
client (Authorization Code + PKCE, matching =apps/web/src/lib/keycloak.ts=)
and its two client roles, =chamadas-staff= and =chamadas-student=, on
container/bundle restart. It does NOT grant those roles to any real user —
do that manually in the Keycloak admin console per staff/student account (or
build a provisioning flow later). =POST /auth/keycloak= also auto-creates a
local =users= row the first time a given Keycloak identity logs in,
promoting it to =STAFF= if the token already carries a staff-ish role.

* Build and deploy

Same hot-deploy mechanism as =contatemeantes= — see that bundle's README for
the full explanation, including the "container restart chowns bundle source
back to appuser" gotcha and its fix
(=docker exec -u 0 fzl-karaf-camel-integration chown -R "$(id -u):$(id -g)"
/opt/karaf/deploy_bundles /opt/karaf/deploy=). Short version:

#+begin_src bash
cd src-projects/karaf_bundles/blueprint-osgi-camel-bundles/chamadasonline
mvn install
#+end_src

Confirm with =bundle:list | grep -i chamadasonline= (state =Active=) and
=camel:route-list= (context =chamadasonlineContext=, routes =Started=), or
=curl http://localhost:9094/chamadasonline/health=.

* Exposing it publicly

=containers/fzl-nginx/nginx-shared/app-server.conf= has a =location
/chamadasonline/= block proxying to port 9094 — same pattern as
=/contatemeantes/=. Its =corsHeaders= are pinned to
=https://wagnermarques.github.io= (the GH Pages origin), unlike
=contatemeantes='s wide-open CORS, since real Bearer tokens flow through
here. Remember nginx bakes its config in at image build time — a plain
config edit does nothing until =docker compose build fzl-nginx=.

* fzl-chamadasonline repo (frontend) changes needed

None to the app code — =apps/web= already implements the full Keycloak flow
and already defaults to =realm=fzlbpms=, =clientId=fzl-chamadasonline=. Only
=.github/workflows/deploy-pages.yml='s env vars need pointing at this stack
instead of Render:

- =VITE_API_URL= → =https://<FZL_PUBLIC_HOSTNAME>/chamadasonline=
- =VITE_KEYCLOAK_URL= → =https://<FZL_PUBLIC_HOSTNAME>/auth/=
- =VITE_KEYCLOAK_REALM= → =fzlbpms=
- =VITE_KEYCLOAK_CLIENT_ID= → =fzl-chamadasonline=

=render.yaml= and =apps/api= become unused (the Node backend isn't deployed
anywhere) — safe to delete once this bundle is verified end to end, or leave
as inert reference.
